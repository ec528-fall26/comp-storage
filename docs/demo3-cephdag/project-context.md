# Computational storage (EC528)

Compiled on 2026-11-11 from Aakash's chats and the result files, during an audit. He has not reviewed this file yet, so treat anything not quoted from him as provisional and correct it when he says otherwise.

## The question

This is his EC528 cloud-computing team project. The research question, from the MOTIVATION-AND-METHOD note in the archive he handed over on 2026-11-03: how should a finite computation graph use machines that each combine compute and storage, and does downstream lookahead improve enough over cheap locality and waiting heuristics to pay for its own planning cost? Compute placement and the storage placement of each output are separate decisions, waiting is an action, and planning time counts in wall time.

## Fixed constraints

From his project documents: optimize time first, with network bytes reported separately and used as a tie-break. Real Ceph is required for system results; local files or a mocked storage service do not substitute. The October lab plan was CPU-only, with no physical-device changes, no publication to the course repository, and no changes to unrelated services.

From him in chat on 2026-11-03: "You can run on aakashpc, do the baseline experiments then we can push further and refine / simplify."

Changes to the lab itself need his yes. On 2026-11-04 he approved restarting only osd.0, and later only the three idle lab workers, with no Docker restart, reformatting, container recreation, or memory-limit increase. Ask again before the next intervention of that kind.
